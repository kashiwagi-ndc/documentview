# Template: 進捗報告メール

## 用途
プロジェクト進捗を顧客・上司・関係者にメールで報告するためのプロンプトを生成する。週次・月次・マイルストーン報告に対応。

## カテゴリ
業務文書系（9）／顧客コミュニケーション系（10）

## 短縮ヒアリング（3問）
1. **報告対象期間**は？（例：1週間 / 1スプリント / 1ヶ月）
2. **読み手**は誰ですか？（顧客／自社上司／社内全体）
3. **特筆事項**はありますか？（リスク発生 / 遅延 / 重要決定 等）

## プロンプト本体テンプレ

```text
# 役割
あなたはプロジェクトマネージャー経験豊富なシニアPMです。
報告は結論先出し・事実ベース・建設的なトーンで書くことを徹底します。

# 背景・前提
- プロジェクト名: [名称]
- 報告対象期間: [期間]
- 報告頻度: [週次 / 月次 / マイルストーン]
- 前回報告からの主な動き: [箇条書き]

# 読み手
- 宛先: [〇〇部長 / 自社上司 / プロジェクト関係者全員]
- 関係性: [社外顧客 / 社内]
- 技術背景: [あり / なし]
- 知りたいこと: [進捗・課題・要決定事項 / 全体感のみ]

# タスク
プロジェクトの進捗報告メールを作成してください。
読み手が30秒で全体を把握でき、必要な意思決定が促せる構成にしてください。

# 出力形式
- 形式: メール本文（件名 + 本文）
- 構成:
  1. 件名（一目で内容が分かる、日付入り）
  2. 冒頭挨拶（簡潔に）
  3. サマリー（進捗ステータス: 順調 / 注意 / 要対応）
  4. 主な進捗（前回からのデルタを箇条書き）
  5. 課題・リスク（あれば。なければ「現時点で大きな課題はありません」と明記）
  6. 次週/次期の予定
  7. 要決定事項（あれば。期限と判断材料を明示）
  8. 結びの挨拶
- 文字数: [400〜800字 / 指定]
- トーン: 敬体・簡潔・建設的

# 特筆事項
[ユーザー入力 — リスク発生時の表現方針、重要決定の扱い等]

# 必須要素
- 件名に進捗ステータス（[順調] / [要注意] 等）を含める
- リスクは隠さず、対策と一緒に提示
- 要決定事項は「期限」と「判断に必要な情報」を明記
- 次のアクションを必ず提示

# やってはいけないこと
- 「順調です」だけで具体性のない報告
- 悪い情報の隠蔽・遅延
- 主観的な評価（「頑張りました」等）
```

## 使い方のコツ
- 顧客向けでも自社向けでも、同じテンプレで宛先・トーンを調整するだけで使える
- リスク発生時は「特筆事項」に「リスクの背景・影響・対策」を明示するとAIが適切なトーンを選ぶ
- 「件名のステータス分類」を社内で統一しておくと、メール一覧で即座に重要度が判別できる

## 想定される失敗パターン
- **悪い情報を曖昧にする** → 「事実ベース」「リスクは隠さず」を必須要素で強化
- **長すぎる本文** → 「文字数」を厳しめに指定
- **アクションが書かれていない** → 「次のアクション」「要決定事項」を必須化
