# Template: ポストモーテム（事後分析）

## 用途
障害対応完了後に作成する事後分析ドキュメント（ポストモーテム）のプロンプトを生成する。再発防止に焦点を当て、責任追及ではなく学びを抽出する。

## カテゴリ
運用/トラブル系（11）

## 短縮ヒアリング（4問）
1. **障害の概要**は？（事象 / 発生〜復旧時刻）
2. **根本原因**は？（既に判明している分のみ）
3. **読み手**は？（社内SRE / マネージャー / 顧客にも共有）
4. **再発防止のアクション候補**はありますか？

## プロンプト本体テンプレ

```text
# 役割
あなたは大規模システム運用のシニアSREです。
ポストモーテムは「責任追及ではなく学習の場」という Blameless Postmortem の文化を徹底します。
人の判断ミスは「より良い判断ができる仕組みがなかった」と捉え、システム/プロセスの改善に転換します。

# 背景・前提
- 障害名: [識別子・概要]
- 発生日時: [YYYY-MM-DD HH:MM]
- 検知日時: [HH:MM]
- 復旧日時: [HH:MM]
- 影響時間: [HH:MM 〜 HH:MM、計N分]
- 重大度: [SEV1 / SEV2 / SEV3]
- 影響範囲: [機能・ユーザー数・売上影響等]
- 根本原因: [既に判明している分]

# 読み手
- 一次読者: [社内SRE / 運用チーム / マネジメント]
- 共有範囲: [社内のみ / 顧客にも共有 / 外部公開（パブリックポストモーテム）]

# タスク
事後分析（ポストモーテム）を作成してください。
責任追及ではなく、システム的・プロセス的な改善点の抽出に集中してください。

# 出力形式
- 形式: Markdown
- 構成:
  1. 📋 サマリー（5W1H + 影響規模）
  2. ⏱️ タイムライン（時系列・分単位）
     - 発生
     - 検知
     - エスカレーション
     - 暫定対応
     - 根本対応
     - 完全復旧
  3. 🔍 根本原因分析
     - 直接原因（何が引き金になったか）
     - 根本原因（なぜそれが起こり得たか — 5 Whys推奨）
     - 寄与要因（複合要因の場合）
  4. 💥 影響評価
     - 機能影響
     - ユーザー影響（人数 / セッション数）
     - 売上・ビジネス影響
     - 信用・SLA影響
  5. 🛡️ 効いた対策・効かなかった対策
     - 既存の防御策で機能したもの
     - 機能しなかったもの（なぜ機能しなかったか）
  6. ✅ アクションアイテム（再発防止策）
     - 優先度（P0=即時 / P1=今四半期 / P2=今後）
     - 担当者
     - 期限
     - 期待効果
  7. 📚 学んだこと（Lessons Learned）
     - 技術面
     - プロセス面
     - 組織面
  8. 🙏 評価できた対応
     - 良かった行動を明示的に称賛
- 文字数: 制約なし（必要な分だけ）
- トーン: 客観的・建設的・Blameless

# 必須要素（Blameless原則）
- 人名を出さず役割名で記述（「A氏が」ではなく「オンコール担当者が」）
- 「ミス」「誤り」ではなく「より良い設計があり得た」と表現
- 良かった点を必ず明記（評価できた対応セクション）
- アクションアイテムには必ず担当・期限・期待効果を含める

# やってはいけないこと
- 個人の責任追及
- 「〇〇さんのせいで」「〇〇すべきだった」等の事後諸葛亮的批判
- 抽象的なアクション（「気をつける」「注意する」等）
- 期限のないアクション
- 既存対策の批判だけで終わる（建設的提案がない）
```

## 使い方のコツ
- **Blamelessが最重要** — 個人攻撃が混ざるとチームの心理的安全性が崩れ、次の障害で正直な情報共有が得られなくなる
- 「5 Whys」を根本原因セクションで使うと表面的な対症療法を防げる
- アクションアイテムは「P0/P1/P2」の優先度を明示することで、実行のリアリティが上がる
- 外部公開する場合は「事業影響」「ユーザー個別情報」を抑えめに記述する別バージョンも作る

## 想定される失敗パターン
- **個人攻撃調になる** → 「人名を出さず役割名」を必須化
- **対症療法的アクションだけになる** → 「5 Whys」「根本原因」を強調
- **期限のないアクション** → 必須要素として「担当・期限・期待効果」を明示
- **良かった点が抜ける** → 「評価できた対応」セクションを必須化
