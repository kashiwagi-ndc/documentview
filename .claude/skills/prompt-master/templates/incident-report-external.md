# Template: 障害一次報告（社外向け）

## 用途
本番障害発生時に顧客向けの一次報告メールを作成するためのプロンプトを生成する。状況がまだ不確定な段階で出す「いま分かっていることだけ」の報告。

## カテゴリ
顧客コミュニケーション系（10）

## 短縮ヒアリング（3問）
1. **障害の概要**は？（事象と発生時刻、現時点で分かっていること）
2. **影響範囲**は？（どの機能・どの顧客が影響を受けるか）
3. **読み手**は誰ですか？（顧客の役員 / 情シス部長 / 現場担当）

## プロンプト本体テンプレ

```text
# 役割
あなたはシステム障害対応のシニアプロジェクトマネージャーです。
お客様の不安を最小化しつつ、事実を正確に伝える報告書を作成するプロフェッショナルです。
推測を断定で書くことは絶対にせず、不明な点は「現在調査中」と明記します。

# 背景・前提
- 発生事象: [事象の概要]
- 発生時刻: [日時]
- 検知方法: [監視アラート / お客様からの連絡 / 内部発見]
- 現時点で分かっていること: [箇条書き]
- 現時点で不明なこと: [箇条書き — これも明示する]
- 対応状況: [調査中 / 復旧作業中 / 復旧済み / 経過観察中]

# 影響範囲
- 影響を受ける機能: [機能名]
- 影響を受けるユーザー: [全顧客 / 特定顧客 / 一部機能利用者のみ]
- 影響の程度: [完全停止 / 一部機能停止 / 性能劣化 / 軽微]

# 読み手
- 役職: [〇〇役員 / 情報システム部長 / 現場担当者]
- 技術背景: [あり / なし]
- 当該システムへの依存度: [基幹 / 重要 / サブ]

# タスク
顧客向けの障害一次報告メールを作成してください。
「事実」「影響」「対応状況」「次の連絡」を明確に分け、推測を入れないこと。

# 出力形式
- 形式: メール本文（件名 + 本文）
- 件名フォーマット: [障害一次報告] 〇〇システムにおける△△障害について（YYYY/MM/DD HH:MM時点）
- 構成:
  1. 件名
  2. 冒頭挨拶（簡潔に）
  3. お詫び（事実を起点に、過剰でなく）
  4. 発生事象（事実のみ・推測なし）
  5. 影響範囲
  6. 現在の対応状況
  7. 原因について（不明なら「現在調査中」と明記）
  8. 復旧見込み（不明なら「明確になり次第ご連絡」）
  9. 次回連絡予定（具体的な時刻 or 「HH時頃」）
  10. 連絡先・お問い合わせ先
  11. 結びの挨拶
- 文字数: 400〜600字
- トーン: 丁寧・誠実・冷静・事実ベース

# 必須要素
- 推測は一切書かない（不明は「現在調査中」と明記）
- 復旧見込みが不明なら「明確になり次第ご連絡」と明記
- 次回連絡時刻を必ず提示（顧客の不安を抑える最大の要素）
- 連絡先を明示
- お詫びは1〜2文に絞り、過剰謝罪しない

# やってはいけないこと
- 「おそらく〇〇が原因」「〇〇と思われる」等の推測
- 「すぐに復旧します」等の根拠なき断定
- 責任転嫁につながる表現（「お客様のご利用環境が…」等）
- 技術的詳細の羅列（読み手が技術職でない場合）
- 言い訳・釈明
```

## 使い方のコツ
- 一次報告は「事実だけ」「次の連絡時刻を約束」が最重要。完璧な原因究明を待たず早く出すべき
- 読み手の役職によってトーンと内容詳細が変わる：
  - **役員向け** → ビジネス影響・対応体制を冒頭
  - **情シス部長向け** → 影響範囲・対応状況を詳しめに
  - **現場担当向け** → 具体的な対処方法・回避策
- 「次回連絡時刻」は必ず守れる時刻にする（守れないと信頼を失う）

## 想定される失敗パターン
- **推測の混入** → 「推測は一切書かない」を必須要素で強化
- **過剰謝罪** → 「お詫びは1〜2文に絞る」を必須化
- **次回連絡時刻なし** → 必須要素として明示
- **責任転嫁表現** → やってはいけないことに明記
