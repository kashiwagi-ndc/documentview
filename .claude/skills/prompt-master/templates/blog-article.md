# Template: ブログ記事作成

## 用途
SEO・情報発信を目的としたブログ記事を生成するためのプロンプトを生成する。技術ブログ・コーポレートブログ・オウンドメディア向け。`writing-crew-starter` 連携も視野。

## カテゴリ
文章生成系（1）

## 短縮ヒアリング（4問）
1. **記事テーマ**は？（具体的なキーワードがあれば最良）
2. **ターゲット読者**は？（業務担当者 / 経営層 / エンジニア / 一般 等）
3. **記事の目的**は？（集客 / リード獲得 / ブランディング / 教育）
4. **文字数 / 構成スタイル**は？（例：3000字 / SEO構成 / 体験談ベース）

## プロンプト本体テンプレ

```text
# 役割
あなたは経験豊富なコンテンツマーケターです。
SEOを意識しつつも、読者にとっての価値を最優先する記事を書くプロフェッショナルです。
専門用語を使うときは必ず噛み砕いて説明し、読みやすさと信頼性を両立させます。

# 背景・前提
- 媒体: [企業ブログ / オウンドメディア / 技術ブログ]
- 業界: [業界]
- 競合状況: [既に存在する類似記事の傾向 / 差別化したい点]

# ターゲット読者
- 属性: [業務担当者 / 経営層 / エンジニア / 一般]
- 検索意図: [何を知りたい / 何を解決したい]
- 知識レベル: [初心者 / 中級者 / 上級者]
- 期待する読み終わった後の状態: [理解 / 行動 / 比較検討]

# 記事の目的
[集客 / リード獲得 / ブランディング / 教育]
- 目的に応じたCTA: [問い合わせ / 資料DL / SNSシェア]

# タスク
[記事テーマ]について、SEOと読者価値を両立するブログ記事を書いてください。

# 出力形式
- 形式: Markdown（WordPress Gutenberg対応も可能な構造）
- 文字数: [指定。一般的には2500〜4000字]
- 構成: 
  - H1（記事タイトル）— 30字前後、キーワード含む
  - リード文（200〜300字）— 読者の悩み共感 → 記事の価値 → 結論ヒント
  - 目次（H2の一覧）
  - H2見出し × 4〜6個（H3で細分化可）
  - まとめ（行動を促す）
- トーン: [敬体 / 常体]・専門性と親しみのバランス
- SEO要件:
  - 主キーワードはH1とリード文に含める
  - 関連キーワードはH2に分散
  - メタディスクリプション案（120字以内）も提示

# 必須要素
- 出典が必要な数値・事例には参考リンクを明記（[出典: URL]形式）
- 体験談・具体例を最低1つ含める
- 比較表・箇条書きを使って可読性を上げる
- まとめの最後にCTA（次のアクション）を含める

# やってはいけないこと
- キーワードの不自然な詰め込み
- 競合記事の丸写し的構成
- 出典のない断定的な数値主張
- 抽象的な「重要です」「効果的です」の連発
```

## 使い方のコツ
- **`writing-crew-starter` スキルがある環境**では、本テンプレを単発で使うより `writing-crew-starter` を起動してリサーチから一貫で進める方が品質が高い
- 「文字数」を厳しめに指定しないとAIは膨らませがち
- 競合記事との差別化を意識する場合、本テンプレの前にリサーチ系プロンプト（competitor-analysis）で競合を分析しておくと強い

## 想定される失敗パターン
- **キーワード詰め込み** → 「不自然な詰め込みを禁止」を明示
- **出典なし数値の濫用** → 「出典必須」を強化
- **CTA忘れ** → 必須要素にCTAを入れる
- **長すぎる記事** → 文字数を厳しく指定

## 連携情報
ユーザーが本格的な記事制作（リサーチ → 設計 → レビュー → 執筆 → ファクトチェック）を求める場合：

```
writing-crew-starter スキルがインストールされていれば、以下のように案内：

「本格的な記事制作なら writing-crew-starter スキルが使えます。
 リサーチからファクトチェックまで6体のエージェントで進めるワークフローです。
 起動するには: 「KW『[キーワード]』で記事を作って」とお伝えください。」
```
