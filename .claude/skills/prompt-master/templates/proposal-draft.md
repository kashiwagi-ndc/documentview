# Template: 提案書ドラフト

## 用途
顧客向けの提案書をドラフトするためのプロンプトを生成する。SI案件・システム提案・サービス提案に使う。

## カテゴリ
業務文書系（9）

## 短縮ヒアリング（4問）
1. **提案テーマ**は何ですか？（例：基幹システム刷新／SaaS導入／DX推進）
2. **読み手**は誰ですか？（顧客の役職・部門・技術背景）
3. **提案の核**は？（コスト削減 / 業務改善 / 売上拡大 / 新規事業 等）
4. **想定文字数 / ページ数** はどれくらいですか？

## プロンプト本体テンプレ

```text
# 役割
あなたは大手SIerのプリセールス経験15年のシニアコンサルタントです。
顧客の経営課題から技術選定までを論理的に橋渡しできるプロフェッショナルです。

# 背景・前提
- 提案テーマ: [テーマ]
- 顧客業界: [業界]
- 提案の核: [コスト削減 / 業務改善 / 売上拡大 / 新規事業 など]
- 既知の課題: [箇条書き]
- 制約: [予算・期間・既存システム制約など]

# 読み手
- 役職: [〇〇部長 / 経営層 / 情報システム部]
- 関係性: [初対面 / 既存取引先]
- 技術背景: [あり / なし]
- 重視するポイント: [ROI / リスク / スピード / ベンダーロックイン回避]

# タスク
顧客の意思決定を促す提案書のドラフトを作成してください。
結論先出し・数値根拠重視・読み手の意思決定基準に沿った構成にしてください。

# 出力形式
- 形式: Markdown
- 構成: 
  1. エグゼクティブサマリー（結論3点）
  2. 顧客課題の整理
  3. 提案する解決策
  4. 期待効果（定量・定性）
  5. 実施スケジュール
  6. 体制と役割分担
  7. リスクと対策
  8. 投資対効果（ROI）
  9. 次のステップ
- 各セクション目安文字数: [指定]
- トーン: フォーマル・論理的・自信を持った断定調

# 必須要素
- 結論はセクション冒頭に
- 数値根拠を必ず併記
- 読み手の懸念点を先回りして示す
- 競合・代替案との差別化を明示

# やってはいけないこと
- 抽象的な「最適化します」「高品質を実現」などの空疎な表現
- 根拠のない断定
- リスクの不開示
```

## 使い方のコツ
- 既知情報が少ない段階でも、仮定を [仮定: 〇〇] と明記してドラフト化できる
- 完成度より「議論のたたき台」として使う方が早く回せる
- 数値根拠を強化したい場合は、別途リサーチ系プロンプト（competitor-analysis 等）で先に調査してから本テンプレに戻る

## 想定される失敗パターン
- **読み手の解像度不足** → 役職だけでなく「重視するポイント」まで指定する
- **抽象的すぎる効果記述** → 「期待効果」セクションに必ず数値目標を入れる指示を強化
- **競合への配慮不足** → 「差別化」を必須要素に追加
