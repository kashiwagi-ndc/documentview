# Template: 議事録整理

## 用途
会議の議事録を整理・要約するためのプロンプトを生成する。録音文字起こし／手書きメモ／口頭サマリーを構造化する用途。

## カテゴリ
業務文書系（9）

## 短縮ヒアリング（3問）
1. **会議の種類**は？（要件定義 / 進捗会議 / 設計レビュー / ステコミ 等）
2. **入力素材**は？（録音文字起こし / メモ / 口頭での要約）
3. **配布先**は？（社内のみ / 顧客にも共有）

## プロンプト本体テンプレ

```text
# 役割
あなたはSIプロジェクトの議事録作成に精通した経験豊富なファシリテーターです。
情報を構造化し、決定事項と宿題を明確に区別できるプロフェッショナルです。

# 背景・前提
- 会議名: [名称]
- 開催日時: [日時]
- 出席者: [一覧]
- 会議目的: [何を決めるための会議だったか]
- 入力素材: [文字起こし / メモ / 録音要約]

# 配布先
- 配布範囲: [社内のみ / 顧客にも共有 / 全関係者]
- 機密区分: [社内秘 / 関係者外秘]

# タスク
入力素材から議事録を構造化して整理してください。
「決定事項」「宿題（ToDo）」「保留事項」を明確に区別し、後で見返したときに会議の結論が一目で分かる構成にしてください。

# 出力形式
- 形式: Markdown
- 構成:
  1. 会議概要（名称 / 日時 / 出席者 / 目的）
  2. アジェンダと進行（時系列）
  3. 主な議論ポイント（論点ごとに要約）
  4. ✅ 決定事項（番号付き、誰が・何を・いつまで・誰の承認で）
  5. 📌 宿題・ToDo（担当者・期限・成果物）
  6. ❓ 保留事項（次回までに確認すべきこと）
  7. 次回会議の予定
- 文字数: 元の素材の20〜30%程度
- トーン: 客観的・事実ベース・敬称略

# 必須要素
- 決定事項と未決定を明確に区別
- 「Aさんが言った」ではなく「〇〇という結論」と整理
- 数値・期限・固有名詞は元素材から正確に抽出
- 議論の途中経過と最終結論を分離

# やってはいけないこと
- 推測で内容を補完する（不明な点は「[要確認]」とマーク）
- 議事録作成者の主観的評価
- 発言者の感情・態度に関する記述
- 「〜と思われる」「〜らしい」等の曖昧表現
```

## 使い方のコツ
- 録音文字起こしを入力にする場合、Claude Code環境では `@meeting-transcript.txt` を Read 指定すると効率的
- 「決定事項」と「ToDo」が混在しがちなので、テンプレで明確に分けるよう指示している
- 顧客配布の場合は「機密区分」を厳しく設定する

## 想定される失敗パターン
- **推測で補完される** → 「不明な点は[要確認]とマーク」を必須要素で強化
- **発言の羅列になる** → 「論点ごとに要約」を強調
- **ToDoの担当者が抜ける** → 「担当者・期限・成果物」を必須項目として明記
