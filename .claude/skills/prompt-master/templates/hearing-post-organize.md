# Template: ヒアリング議事録→要件整理

## 用途
ヒアリング後の議事録・メモから、要件一覧・課題マップ・次回確認事項を構造化整理するプロンプトを生成する。ヒアリングの「成果物化」を効率化。

## カテゴリ
要件ヒアリング/上流系（14）

## 短縮ヒアリング（3問）
1. **入力素材**は？（@議事録ファイル / 文字起こし / メモ）
2. **整理の目的**は？（要件定義書化 / 次回ヒアリング準備 / 提案書作成）
3. **配布先**は？（社内のみ / 顧客に確認依頼）

## プロンプト本体テンプレ

```text
# 役割
あなたはSI上流工程のヒアリング整理に精通したシニアビジネスアナリストです。
ヒアリングメモから構造的な要件・課題・宿題を抽出し、後工程に繋がる成果物を作成するプロフェッショナルです。
推測と確定を厳密に区別し、抜け漏れを「次回確認事項」として明示します。

# 背景・前提
- ヒアリング日時: [YYYY-MM-DD]
- ヒアリング対象: [〇〇社 / 〇〇部門]
- 出席者: [顧客側 / 自社側]
- ヒアリング目的: [初回要件確認 / 詳細確認 / 課題深掘り]
- 案件種別: [新規開発 / 改修 / リプレース / 移行]

# 入力素材
[Claude Code向け] @[議事録/文字起こしファイル] を Read
[他AI向け] 以下:
[議事録貼り付け]

# 整理の目的
- [要件定義書化 / 次回ヒアリング準備 / 提案書作成]

# 配布先
- [社内のみ / 顧客に確認依頼]

# タスク
入力素材から、構造化された要件整理ドキュメントを作成してください。
ヒアリングで触れた話題を漏らさず、かつ「確定」「推定」「次回確認」を厳密に区別してください。

# 出力形式
- 形式: Markdown
- 構成:
  1. 📋 ヒアリング概要
     - 日時 / 出席者 / 目的
     - ヒアリング全体のサマリー（3〜5行）
  2. 🎯 顧客のビジネスゴール（推定）
     - 表明されたゴール
     - 言及があった背景・動機
     - 暗黙的に感じられた優先事項
     - 確度タグ
  3. ✅ 確定した要件
     - 機能要件
       - 要件ID / 内容 / 出所（誰の発言）
     - 非機能要件
     - 制約事項
     - 前提条件
  4. 🤔 推定された要件（要確認）
     - 要件ID / 内容 / 推定根拠 / 確認方法
  5. ❓ 不明・確認事項
     - 質問内容 / 確認相手 / 期限
     - これらが明確化しないと進めない事項を優先順位付け
  6. ⚠️ 課題・リスク
     - 課題ID / 内容 / 影響度 / 緊急度 / 対応案
     - 課題マップ（4象限：影響大×頻度高/低、影響小×頻度高/低）
  7. 📝 宿題・ToDo
     - 自社側
       - ToDo / 担当者 / 期限 / 成果物
     - 顧客側
       - 確認依頼 / 期限
  8. 🎭 顧客の関心事・温度感
     - 強く反応した話題
     - 抵抗・懸念があった話題
     - 意思決定者の関与度
  9. 💡 次のステップの提案
     - 次回ヒアリングのテーマ
     - 中間成果物の提案
     - 並行して進められること
  10. 📌 議事録としてのまとめ（顧客送付用）
      - 配布先が顧客にも含まれる場合、顧客向けに整形した版を別途作成
      - 内部メモは除外
      - 確認依頼事項を明示

# 確度表記の強制
各記述に以下のタグを付与:
- [確定] 議事録から明確に確認できる
- [推定] 言葉のニュアンスから推測（理由併記）
- [要確認] 議事録に記載なし・矛盾あり

# 整理の原則
- 「Aさんが〇〇と言った」ではなく「〇〇という結論/課題」に整理
- 主観的評価を避ける（「お客様は乗り気だった」等）
- 数値・期限・固有名詞は議事録から正確に引用
- 議事録に書かれていないことを補完しない（要確認に分類）

# 必須要素
- 要件は「機能 / 非機能 / 制約 / 前提」で分類
- 課題マップを4象限で可視化
- 宿題は担当・期限・成果物を必ず明示
- 確度タグを各記述に付与
- 次のステップ提案を含める

# やってはいけないこと
- 議事録にない要件を「推測で」確定として書く
- 個人攻撃調の記述（「Aさんは理解が浅かった」等）
- 顧客向け版に内部評価を含める
- 課題を抽象的に書く（「コミュニケーションが課題」等）
- 「以下、議事録の通り」と整理を放棄
```

## 使い方のコツ
- **議事録は録音文字起こし or 詳細メモを推奨**—サマリーだけでは整理が浅くなる
- 「顧客の関心事・温度感」セクションは社内戦略に直結する貴重な情報
- 顧客送付用と社内用を分けると、温度感や内部評価を漏らさず分けられる
- 「課題マップの4象限」を可視化することで、優先順位の議論が進む

## 想定される失敗パターン
- **発言の羅列で終わる** → 「結論/課題に整理」を必須化
- **推測の混入** → 確度タグを必須化
- **宿題の担当者・期限抜け** → 「担当・期限・成果物を明示」を必須化
- **顧客送付用と社内用の混在** → 配布先に応じた分離を必須化
- **議事録にない補完** → 「議事録にないことは要確認に分類」を強化
