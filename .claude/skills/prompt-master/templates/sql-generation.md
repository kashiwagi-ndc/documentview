# DBエンジン固有の注意点
[エンジンに応じて]
- PostgreSQL: 日付関数（date_trunc）、ウィンドウ関数の活用
- MySQL: 8.0未満ではウィンドウ関数なし、GROUP BYの挙動注意
- Oracle: ROWNUMの位置、ANSI JOIN推奨
- BigQuery: パーティション・クラスタリング、UNNEST活用
- Snowflake: QUALIFY節、Time Travel

## 使い方のコツ
- **DBエンジンとバージョンの明示は最重要** — これがブレるとクエリが動かない
- 行数概算を伝えると、AIが性能を意識したクエリを書く
- 「検証SQL」を出させることで、本番投入前のスポットチェックがしやすい
- BigQuery / Snowflake等のクラウドDBは料金にも影響するので、性能要件と同時にコスト要件も伝えると良い

## 想定される失敗パターン
- **DBエンジン未指定で方言エラー** → 「DBエンジン必須化」を最初に確認
- **NULL の見落とし** → 「NULLの扱いを明示」を必須化
- **タイムゾーン問題** → 「日時集計時のタイムゾーン考慮」を必須化
- **インデックスを使えない書き方** → 「インデックスを破壊する関数禁止」を強化
