# Template: 要件ヒアリング事前準備

## 用途
顧客とのヒアリングに臨む前に、整理すべき情報・仮説マップ・聞くべき項目をまとめるプロンプトを生成する。SI上流工程の最初の砦。

## カテゴリ
要件ヒアリング/上流系（14）

## 短縮ヒアリング（4問）
1. **プロジェクト種別**は？（新規開発 / 改修 / リプレース / 移行）
2. **業界・業種**は？（金融 / 製造 / 流通 / 医療 / 公共 / SaaS）
3. **ヒアリング相手**は？（役職・部門）
4. **現状理解度**は？（既知の情報があれば箇条書きで）

## プロンプト本体テンプレ

```text
# 役割
あなたはSI上流工程に20年以上の経験を持つシニアコンサルタント兼プロジェクトマネージャーです。
顧客との要件ヒアリング前に、整理すべき情報・仮説・聞くべき項目を体系化して、効率的なヒアリングを実現するプロフェッショナルです。

# 背景・前提
- プロジェクト種別: [新規開発 / 改修 / リプレース / 移行 / 統合]
- 業界・業種: [金融 / 製造 / 流通 / 医療 / 公共 / SaaS]
- 案件規模: [小規模 / 中規模 / 大規模]
- 想定システム種別: [基幹系 / 情報系 / 顧客向け / 社内向け]
- 想定スケジュール: [短期 / 中期 / 長期]
- 既知の情報（現状理解度）:
  - [箇条書き]

# ヒアリング相手
- 役職: [〇〇役員 / 部長 / 課長 / 現場担当]
- 部門: [情報システム部 / 業務部門 / 経営層 / 複数部門]
- 技術背景: [あり / なし]
- 関係性: [初対面 / 既存取引先 / 紹介]

# 想定ヒアリング時間
- [60分 / 90分 / 半日 / 複数回]

# タスク
ヒアリング前に整理すべきことを体系化し、当日効率的に聞くための準備リストを作成してください。

# 出力形式
- 形式: Markdown
- 構成:
  1. 📋 案件理解の仮説マップ
     - 想定されるビジネスゴール（仮説）
     - 想定される技術課題（仮説）
     - 想定されるステークホルダー
     - 既知 vs 不明 の整理
  2. 🎯 ヒアリングの目的設定
     - このヒアリングで明確にしたい3つのこと
     - 二次的に確認したいこと
     - 今回は深掘りしないこと（次回以降）
  3. 📚 事前に調べておくべきこと
     - 業界知識（業界特有の用語・慣習）
     - 想定される競合システム
     - 法規制・コンプライアンス事項
     - 一般的なシステム構成パターン
  4. 🔍 当日聞くべき質問（優先順位順）
     - 必須質問（必ず聞く・5〜7問）
     - 推奨質問（時間あれば聞く・5〜10問）
     - 任意質問（場の流れで聞く）
  5. 📊 質問の構造化（業界別ノウハウ反映）
     - 機能要件
     - 非機能要件（性能・可用性・セキュリティ）
     - 運用要件
     - 移行要件
     - プロジェクト要件
  6. 💡 業界特有の留意点
     - [業界]で特に重要な確認事項
     - センシティブで段階的に聞くべき事項
     - 業界特有の規制・慣習
  7. 🚫 聞いてはいけないこと（または段階的に）
     - センシティブな組織内政治
     - 競合関係への直接言及
     - 個人責任に関する質問
  8. 📝 持参すべき資料・道具
     - 提案概要資料
     - 過去事例
     - 業界レポート
     - 質問リスト
  9. 🎭 想定される反応と切り返し
     - 「予算は決まってない」→ [対応方針]
     - 「現状で困っていない」→ [対応方針]
     - 「他社にも相談中」→ [対応方針]
  10. 📌 ヒアリング後の整理予定
     - 議事録のフォーマット
     - 次回までに準備するもの

# 必須要素
- 質問は「具体例つきの聞き方」で記述
- 業界特有の留意点を必ず含める
- 「聞き漏らし防止チェックリスト」を網羅
- 想定される反応と切り返しを準備

# やってはいけないこと
- 機能要件だけで非機能要件を抜く
- 抽象的な質問（「ご要望をお聞かせください」だけ）
- 顧客の暗黙ルールを無視した直球質問
- 業界知識を欠いたままの基礎的質問（信頼を失う）

# 業界別ノウハウ（自動展開）
[業界に応じて以下を反映]

【金融】
- 規制対応（個人情報・FISC・PCI DSS）・監査要件・システム連携・帳票要件
- センシティブ: 内部統制の現状（直球で聞かない）

【製造】
- 既存システム連携（生産管理・PLM・MES）・現場運用・図面管理・トレーサビリティ
- センシティブ: 現場の暗黙ルール（観察重視）

【流通/小売】
- 季節変動・繁忙期・店舗運用・POS連携・在庫精度
- センシティブ: 在庫差異・廃棄の実態

【医療】
- 個人情報（患者情報）・電子カルテ規格（HL7/FHIR）・薬機法・診療報酬
- センシティブ: 患者情報の取扱い（細心の注意）

【公共】
- 調達ルール・既存契約・システム間連携・自治体クラウド・マイナンバー
- センシティブ: 政治的背景（明示的に聞かない）

【SaaS/Web】
- スケール・SLA・マルチテナント・API連携・データ可搬性
- センシティブ: 競合への配慮
```

## 使い方のコツ
- **業界を明示することで業界別ノウハウが自動展開**される
- 「ヒアリング相手の役職」によって質問の深さが変わる：
  - 役員 → ビジネスゴール・予算感
  - 部長 → 部門横断の課題
  - 現場担当 → 具体的な業務フロー
- 「想定される反応と切り返し」が地味に効く—現場で焦らない
- 質問は10〜15問程度に絞る（90分で全部聞ける数）

## 想定される失敗パターン
- **質問が抽象的** → 「具体例つきの聞き方」を必須化
- **非機能要件の抜け** → 「聞き漏らし防止チェックリスト」を網羅
- **業界知識不足** → 業界別ノウハウを自動展開
- **想定問答なし** → 「想定される反応と切り返し」を必須化
