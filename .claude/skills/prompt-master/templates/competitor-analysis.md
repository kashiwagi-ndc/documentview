# Template: 競合アプリ比較

## 用途
新規アプリ開発・既存サービスのポジショニング検討等で、競合製品を体系的に比較するためのプロンプトを生成する。`ai-employee` 連携も視野。

## カテゴリ
リサーチ/競合調査系（6）

## 短縮ヒアリング（4問）
1. **比較対象アプリ**は？（具体的な製品名 3〜5個）
2. **比較軸**は？（機能 / 価格 / UX / 対象ユーザー / 技術スタック 等）
3. **目的**は？（新規開発の機能棚卸し / 提案書 / 技術選定 / ピッチ資料）
4. **出力形式**の希望は？（標準プロンプト / ai-employee連携 / ai-editorial連携）

## プロンプト本体テンプレ（出口A：標準プロンプト）

```text
# 役割
あなたは[業界]に精通した業界アナリストです。
複数の競合製品を客観的に比較し、新規参入者の機会領域や差別化軸を見抜くプロフェッショナルです。
情報の鮮度と出典の信頼性を常に重視し、不確実な情報は明示します。

# 背景・前提
- 比較対象カテゴリ: [タスク管理アプリ / SaaS会計ソフト 等]
- 比較対象製品: [製品A / 製品B / 製品C ...]
- 調査の目的: [新規開発の機能棚卸し / 提案書 / 技術選定 / 市場理解]
- 既知の情報: [箇条書き — 既に分かっていること]

# 調査範囲
- 対象製品: [上記の3〜5個]
- 地域: [国内 / グローバル / 特定地域]
- 期間: [直近1年 / 最新リリースまで]

# 比較軸（3〜5個）
1. [軸1 — 例：主要機能]
2. [軸2 — 例：価格モデル]
3. [軸3 — 例：対象ユーザー層]
4. [軸4 — 例：技術スタック・拡張性]
5. [軸5 — 例：エンタープライズ対応]

# 出典の扱い
- 公式情報を最優先（公式サイト・リリースノート・公式ドキュメント）
- 次にレビューサイト（G2 / Capterra / ProductHunt）
- 各項目に必ず出典URLを明記
- 不確実な情報は「[要確認]」とマーク
- 推測情報は「[推測]」とマークし、根拠も併記

# 鮮度
- 直近12ヶ月の情報を優先
- それ以前の情報は「[20XX年時点]」と注釈

# タスク
上記の競合製品を上記の比較軸で詳細に比較し、新規参入の機会領域や差別化軸を抽出してください。

# 出力形式
- 形式: Markdown
- 構成:
  1. 📋 サマリー（5〜7行）
  2. 📊 比較表（縦：機能/軸、横：製品）
  3. 🔍 各製品の特徴詳述
     - 強み
     - 弱み
     - ターゲットユーザー
     - 価格帯
     - 注目すべき独自機能
  4. 💡 差別化軸の分析
     - 各製品がどこで戦っているか（ポジショニング）
     - 競合間のギャップ（誰もカバーしていない領域）
     - 新規参入余地
  5. 🎯 [目的に応じた結論セクション]
     - 新規開発の場合: 取り込むべき機能 + 差別化機能の提案
     - 提案書の場合: 顧客に提示する選定ポイント
     - 技術選定の場合: 推奨・採用根拠・リスク
  6. 📚 出典リスト

# スコープ縮退ガード
- 比較表は3〜5製品に絞り、深掘り優先
- 各製品の機能比較はTOP5機能に絞る
- 網羅性よりも「実用的な洞察」を重視

# 差別化軸の必須化
比較表で終わらせず、「結局どこが違うのか」「この市場で勝つならどこか」の差別化軸を必ず出力に含めること。

# やってはいけないこと
- 出典のない断定的な数値・市場シェア記述
- 製品の良い面だけ・悪い面だけ偏った記述
- 古い情報を最新として扱う
- 「最強」「唯一」等の絶対表現
```

## プロンプト本体テンプレ（出口B：ai-employee 連携起動文）

```text
ai-employee で動かして:

テーマ: [比較対象カテゴリ]競合比較（[製品A] / [製品B] / [製品C]）

リサーチ観点:
1. [軸1]の比較（特に [深掘りしたいポイント]）
2. [軸2]の比較
3. [軸3]の比較

目的: [新規参入の判断材料 / 提案書根拠 / 技術選定資料]

特に注目したい点:
- [注目点1]
- [注目点2]
- [注目点3]
```

## 使い方のコツ
- **比較対象は3〜5個が最適** — 多すぎると各製品の深掘りが浅くなる
- **目的を明確にする**と出力の粒度が最適化される（同じ「Notion vs Obsidian」でも、新規開発用と提案書用では結論が違う）
- **`ai-employee` がある環境では出口Bを優先** — リサーチ→レポート→スライドまで自動生成される
- 公開直前の新機能は情報が古い可能性があるので、「直近の公式リリースノートを参照」と明示

## 想定される失敗パターン
- **比較対象が多すぎて浅い** → 「3〜5製品に絞る」を強調
- **公平性に欠ける比較** → 「強みと弱みを必ず両方記述」を必須化
- **差別化軸の考察なし** → 「差別化軸の必須化」を強化
- **古い情報の混入** → 「鮮度の明示」を強化
