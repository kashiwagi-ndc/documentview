# Template: 質問リスト生成（業界別）

## 用途
ヒアリング当日に使う質問リストを業界・案件種別に応じて生成するプロンプトを生成する。「具体例つき・優先順位付き」で現場でそのまま使える形にする。

## カテゴリ
要件ヒアリング/上流系（14）

## 短縮ヒアリング（4問）
1. **業界・業種**は？
2. **プロジェクト種別**は？
3. **ヒアリング時間**は？（60分 / 90分 / 半日）
4. **重点的に確認したい領域**は？（業務要件 / 技術要件 / 全般）

## プロンプト本体テンプレ

```text
# 役割
あなたは要件定義フェーズに精通したシニアコンサルタントです。
業界特性・案件種別・相手の役職を考慮した、現場ですぐ使える質問リストを作成するプロフェッショナルです。
質問は必ず「具体例つきの聞き方」で構成し、若手SEに渡しても即戦力になる質を目指します。

# 背景・前提
- 業界・業種: [業界]
- プロジェクト種別: [新規開発 / 改修 / リプレース / 移行]
- 想定システム種別: [基幹 / 情報系 / 顧客向け / 社内向け]
- ヒアリング時間: [60分 / 90分 / 半日 / 複数回]
- 重点領域: [業務要件 / 技術要件 / 全般]

# ヒアリング相手
- 役職: [〇〇]
- 部門: [〇〇]
- 技術背景: [あり / なし]

# タスク
ヒアリング当日に使う質問リストを生成してください。
各質問は「具体例つき・聞き方の例文付き」で記述し、優先順位を明示してください。

# 出力形式
- 形式: Markdown
- 構成:
  1. 📋 ヒアリングの目的とゴール
     - このヒアリングで明確にしたいこと
  2. ⏱️ タイムテーブル案
     - アイスブレイク（5分）
     - 現状確認（15分）
     - 課題深掘り（20分）
     - 要件確認（30分）
     - 次のステップ確認（10分）
  3. ❓ 質問リスト（業務要件）
     - 【必須・優先度高】質問1
       - 聞き方の例文: 「〇〇について教えてください。具体的に△△のような状況はありますか？」
       - 想定回答パターン: [A] [B] [C]
       - 深掘り質問: 「もし[A]の場合、〇〇はどうされていますか？」
     - 【必須・優先度高】質問2
       - ...
     - 【推奨】質問3
       - ...
  4. ❓ 質問リスト（非機能要件）
     - 性能（同時利用数 / レスポンス / データ量）
     - 可用性（稼働率 / RTO/RPO / メンテナンス）
     - セキュリティ（認証 / 権限 / 監査ログ）
     - 拡張性・保守性
  5. ❓ 質問リスト（運用要件）
     - 運用体制
     - 監視・バックアップ
     - 障害時対応
  6. ❓ 質問リスト（移行要件） ※該当時
     - データ移行
     - 並行稼働
     - 切戻し条件
  7. ❓ 質問リスト（プロジェクト要件）
     - 体制
     - スケジュール
     - 検収条件
     - 教育・引き継ぎ
  8. 💡 業界特有の必須質問
     - [業界別の重要質問]
  9. ⚠️ センシティブで段階的に聞く質問
     - [業界別の慎重質問]
  10. 🎯 想定される反応と次の質問
     - 「決まっていません」→ [次の質問]
     - 「現状で問題ない」→ [次の質問]
     - 「専門用語で不明」→ [噛み砕いた質問]
  11. 📝 ヒアリング後の確認事項
     - 議事録の確認依頼
     - 次回の予定
     - 持ち帰り宿題

# 質問の「具体例つき聞き方」の原則
❌ 悪い例:
  - 「性能要件はありますか？」

✅ 良い例:
  - 「ピーク時の同時利用者数はどれくらいを想定されていますか？
     例えば朝9時の業務開始直後など、特に集中する時間帯はありますか？」
  
  - 「現在のシステムで遅いと感じる処理はありますか？
     具体的にどの画面・どの操作でしょうか？」

# 優先順位の付け方
- 【必須・優先度高】: このヒアリングで必ず確認する（5〜7問）
- 【推奨】: 時間あれば確認（5〜10問）
- 【任意】: 場の流れで聞く（残り時間で）

# 必須要素
- すべての質問に「聞き方の例文」を付ける
- 想定回答パターンと深掘り質問を併記
- 業界特有の必須質問を含める
- センシティブ質問は「段階的に」と明記
- タイムテーブルで時間配分を示す

# やってはいけないこと
- 抽象的な質問だけのリスト
- Yes/Noで終わる質問ばかり（深掘りに繋がらない）
- 業界の暗黙ルールを無視した直球質問
- 専門用語の連発（相手に技術背景がない場合）
- 「他には？」を多用（質問者の準備不足が露呈）
```

## 使い方のコツ
- **「聞き方の例文」が最も価値**—これがあるだけで現場で迷わない
- 「想定回答パターン」も用意することで、応答に応じた深掘りが事前準備できる
- タイムテーブルを意識すると、当日「時間が足りない」を防げる
- 若手SEに渡す場合は、深掘り質問の例を多めに用意

## 想定される失敗パターン
- **抽象的な質問** → 「具体例つき聞き方」を必須化
- **Yes/No質問** → 「想定回答パターンと深掘り」を必須化
- **時間配分なし** → タイムテーブル案を必須化
- **業界配慮なし** → 業界特有の必須質問・センシティブ質問を必須化
