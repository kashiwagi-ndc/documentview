# リサーチ系の他スキル連携仕様

リサーチ/競合調査系（カテゴリ6）のプロンプト生成時、ユーザー環境にあるリサーチ系スキルと連携するための仕様。

---

## 1. 連携対象スキル一覧

| スキル名 | 用途 | 入力 | 出力 |
|---|---|---|---|
| `ai-employee` | リサーチ→レポート→スライド（高速版） | テーマ1個 | `output/research-notes.md`<br>`output/report.html`<br>`output/presentation.html` |
| `ai-editorial` | リサーチ→6チャネル展開 | テーマ1個 | 6種類のコンテンツ |
| `writing-crew-starter` | 記事制作（リサーチ→設計→執筆） | KW・テーマ | ブログ記事 |

連携可能なエージェント（直接呼び出し）:

| エージェント | 用途 |
|---|---|
| `content-researcher` | リサーチ単体（クエリ拡張・フォールバック） |
| `presentation-researcher` | リサーチ単体（高速版・WebSearch 3回固定） |
| `crew-researcher` | 記事制作専用リサーチ |

---

## 2. 環境認識ロジック

リサーチ系プロンプト生成時、必ず以下を確認する。

### 確認コマンド

```bash
ls ~/.claude/skills/ 2>/dev/null
ls ~/.claude/agents/ 2>/dev/null
```

### 判定ロジック

| 存在するスキル | 提示する出口 |
|---|---|
| `ai-employee` あり | 出口B（提案資料化） |
| `ai-editorial` あり | 出口C（多面展開） |
| `writing-crew-starter` あり | 出口C派生（記事化） |
| いずれもなし | 出口Aのみ提示 |

---

## 3. 3つの出口

### 出口A: 標準プロンプト（他AIに貼る用）

ChatGPT / Claude / Gemini 等にコピペで使えるMarkdown形式のリサーチプロンプト。

#### 適している用途
- 一回限りの調査
- 手元で手動制御したい
- 他AIとの比較を行いたい

#### 出力例

```text
# 役割
あなたは [業界] の業界アナリストです。

# 背景・前提
- [調査対象]
- [前提条件]

# 調査対象
[製品/サービス/技術 などの一覧]

# 比較軸
1. [軸1]
2. [軸2]
3. [軸3]

# 出典の扱い
- 各項目に出典URLを必ず明記
- 公式情報を優先、レビューサイトも参照
- 不確実な情報は「[要確認]」とマーク

# 鮮度
[直近1年 / 最新リリースまで] の情報を優先

# 出力形式
- 形式: Markdown
- 構成: 比較表 + 各社の特徴詳述 + 差別化軸の考察 + 出典リスト

# 差別化軸の必須化
比較表で終わらせず、「結局どこが違うのか」「この市場で勝つならどこか」の差別化軸を必ず出力に含めること。
```

### 出口B: ai-employee 連携（レポート＋スライド）

`ai-employee` スキルを起動するための整形済みテーマを生成。

#### 適している用途
- 提案書・社内資料に仕上げたい
- 短時間（5分前後）で完結させたい
- レポートとスライドの両方が欲しい

#### 出力例

````markdown
✅ ai-employee 用の起動文を生成しました。

【ai-employee 起動文】

```text
ai-employee で動かして:

テーマ: タスク管理アプリ競合比較（Notion / Obsidian / Logseq）

リサーチ観点:
1. 主要機能の比較（特に同期・拡張性・オフライン対応）
2. 価格モデルと無料枠の比較
3. ターゲットユーザー層と差別化ポイント
```

【使い方】
1. 上記の起動文をコピー
2. 新しいClaude Codeセッション or 同セッションで貼り付け
3. ai-employee がリサーチ → レポート（report.html）→ スライド（presentation.html）を生成

【生成物の置き場所】
- output/research-notes.md
- output/report.html
- output/presentation.html

💡 標準プロンプト版も欲しい場合は「Aも欲しい」とお知らせください。
````

#### テーマの磨き方

`ai-employee` は「テーマ1個」で動くシンプル設計だが、テーマの書き方で出力品質が大きく変わる。プロンプトマスターが以下のように整形する：

```
❌ 弱いテーマ: 「タスク管理アプリ調べて」
✅ 強いテーマ: 「タスク管理アプリの主要3製品（Notion / Obsidian / Logseq）について、
              機能比較・価格比較・差別化軸の3観点で、
              新規参入の余地を判断する材料として整理」
```

テーマに必ず含めるべき要素：
- 対象（具体的な製品名・カテゴリ）
- 観点（何を比較するか・3〜5個）
- 目的（結果を何に使うか）

### 出口C: ai-editorial 連携（6チャネル展開）

`ai-editorial` スキルを起動するための整形済みテーマを生成。

#### 適している用途
- 記事・YouTube・SNSなど複数チャネルで発信したい
- リサーチ結果を多面的に活用したい
- メディア戦略として整理したい

#### 出力例

````markdown
✅ ai-editorial 用の起動文を生成しました。

【ai-editorial 起動文】

```text
ai-editorial で動かして:

テーマ: 2026年タスク管理アプリ最新動向と新規参入余地

リサーチ観点:
- 主要プレイヤー（Notion / Obsidian / Logseq 等）の動向
- 価格モデルの変化
- ユーザー層の変化
- 新規参入の機会領域
```

【使い方】
1. 上記の起動文をコピー
2. Claude Code で貼り付け
3. ai-editorial がリサーチ → 6種類のコンテンツを並列生成
   - リサーチレポート（HTML）
   - ブログ記事（WordPress Gutenberg形式）
   - Xスレッド
   - YouTube台本（10分尺）
   - メルマガ
   - インフォグラフィック（複数枚）

💡 標準プロンプト版も欲しい場合は「Aも欲しい」とお知らせください。
````

## 4. 出口選択の聞き方

### 標準フロー

```
プロンプトマスター: 「リサーチ系として進めます。
                    
                    結果をどう活用しますか？
                    
                    A) 自分でChatGPT等に貼って参照したい
                    B) 提案書/レポート/スライドに仕上げたい（ai-employee連携）
                    C) 記事・SNS等の複数チャネルで発信したい（ai-editorial連携）
                    
                    どれが近いですか？」
```

### スキル未インストール時

`ai-employee` / `ai-editorial` がインストールされていない場合：

```
プロンプトマスター: 「リサーチ系として進めます。
                    
                    現在の環境では出口Aのみ利用可能です。
                    （ai-employee / ai-editorial が ~/.claude/skills/ にあれば
                     B/C も選択できます）
                    
                    Aで進めてよろしいですか？」
```

## 5. シーン別の推奨出口

| シーン | 推奨出口 | 理由 |
|---|---|---|
| 新規開発の競合調査 | B（ai-employee） | レポートで提案書化しやすい |
| 技術選定 | A | 手元で詳細制御したい |
| 提案書用市場調査 | B（ai-employee） | スライドつきで顧客提示できる |
| 顧客向け説明資料 | B（ai-employee） | スライドが直接使える |
| 記事化したい知見 | C（ai-editorial） | 多チャネル展開できる |
| ピッチ用 | B（ai-employee） | スライドが必要 |
| 社内ナレッジ蓄積 | A or B | 用途次第 |
| ベンダー比較 | A | 細かく制御したい |
| 規制/コンプラ調査 | A | 精度重視で手動チェック |

## 6. テーマ磨き役の役割

`ai-employee` / `ai-editorial` の出力品質は、与えるテーマの質に強く依存する。
プロンプトマスターは以下の3点でテーマを磨く。

### 6.1 具体化

抽象的なテーマを具体的に。

```
弱: 「タスク管理アプリ」
強: 「タスク管理アプリの主要3製品（Notion / Obsidian / Logseq）」
```

### 6.2 観点の明示

リサーチ観点を3〜5個明示。

```
弱: 「比較してほしい」
強: 「機能・価格・対象ユーザー・拡張性・オフライン対応の5観点で比較」
```

### 6.3 目的の明示

結果を何に使うか明示。これがあるとAIが出力の粒度を最適化できる。

```
弱: 「調べたい」
強: 「新規参入の判断材料として整理」
強: 「顧客への提案書の根拠として」
強: 「社内技術選定の材料として」
```

### 磨き後のテーマ例

```
テーマ: タスク管理アプリの主要3製品（Notion / Obsidian / Logseq）について、
       機能・価格・対象ユーザー・拡張性・オフライン対応の5観点で比較し、
       新規参入の機会領域を特定する。
       
       特に注目したい点:
       - エンタープライズ向けの機能差
       - ローカル動作の重要性
       - プラグインエコシステムの活発度
```

## 7. 出口AとB/Cの併用提案

出口B/Cで進める場合でも、ユーザーが希望すれば**標準プロンプト版（A）も併せて生成**する。

```
ユーザー: 「Bでお願いしたいけど、Aも欲しい」

→ ai-employee 起動文 + 標準プロンプト を両方提示
→ それぞれの使い分けを説明
```

これにより、**「ai-employeeで全体像をつかみ、Aで気になる箇所だけ深掘り」**といった併用ができる。
