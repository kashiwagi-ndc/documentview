# フィードバック収集（その場＋まとめ）

メンバーがキット（スキル/ドキュメント）を使って感じたことを集め、改善に回すための進行役の動き。
**正本は `docs/feedback/feedback-log.md`。** GitHub Issue/Slack へ流す場合もログが正本（二重管理しない）。

---

## いつ起動するか

- 「フィードバック」「使いにくい」「わからない」「ここ直してほしい」「バグ」「良かった」と言われたら、このモードに入る。
- 各工程の途中で詰まった様子があれば、進行役から「**今のところ、フィードバックしておきますか？**」と軽く促してよい（その場で拾うのが一番大事）。

## その場フィードバック（3問だけ・低摩擦）

困った"その瞬間"に拾う。長く聞かない。次を会話で埋める：
1. **対象**：どのスキル/ドキュメントの話か（直前に使っていたものを推測して提示してよい）
2. **種類と内容**：使いにくい/わからない/バグ/要望/良かった ＋ 何が起きたか
3. **重要度**：高（止まる）／中（不便）／低（あれば嬉しい・感想）
   - 「どうなら良いか」は言ってくれたら拾う（任意）。名前は任意（**匿名OK**）。

→ まとめて `docs/feedback/feedback-log.md` の表に**1行追記**する（新しいものを上に）。日付を入れる。状態は「未対応」。

## まとめフィードバック（記入式）

腰を据えて書きたい人向け：`docs/templates/フィードバック.md` または入力フォーム `docs/templates/template-form.html` の「フィードバック」タブ → CSV出力。
受け取ったCSV/メモは、進行役がログの表に転記する（重複しないよう、正本はログに集約）。

## 外部チャネルへ流す（あれば・任意）

ログに追記したうえで、チャネルが**連携済みなら**コピーを流す（**許可を得てから・認証情報は出さない**）：
- **GitHub Issue**：`feedback` ラベルで起票。テンプレは `docs/examples/github-issue-template_kit-feedback.md`。Issue番号をログ行に書いて紐付け。
- **Slack/Teams**：要約を投稿（「新しいフィードバック：対象/種類/重要度/内容」）。スレッドで議論。
- 連携が無ければログだけでよい（チャネルは後から足せる）。

## 改善ループ（ためたら回す）

- **週次 or スプリント末**に、進行役（または担当）がログを上から確認。`/ai-reviewer` でまとめてレビューしてもよい。
- 高→中→低 でトリアージ。**対応/見送り**を決め、状態を更新（見送りは理由も）。
- 対応はスキル/ドキュメントへ反映 → 版up。**「良かった」も拾い、削ってはいけない所を把握**する。
- ⑧ふりかえりとは別物（⑧＝プロジェクトの進め方、こちら＝キット自体の改善）だが、⑧の場でまとめて確認してもよい。

## 原則
- **捨てない・透明に**：全部ログに残し、対応も見送りも記録する。
- **匿名OK・本音優先**：重要度だけ必須、名前は任意。
- **その場が命**：後から「どこが不便だっけ」は忘れる。困った瞬間に拾う。
