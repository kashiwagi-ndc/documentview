# 検証ゲートの例（自動チェックの仕掛け／Hooks）

> 工程⑥の「検証ゲート」を、**人の気合いでなく自動で**効かせるための設定例です。
> Claude Code の Hooks（フック＝ある操作のあとに自動でコマンドを走らせる仕組み）を使います。
> ねらい：**ファイルを直したら自動でテスト／文法チェックが走り、失敗が見える**ようにする。

## やさしい説明
- 人が「テストしてね」と言わなくても、**編集のたびに自動で確認**が走る。
- これがあると、AIが直したコードの問題に**早く気づける**。
- 設定は環境ごとに違うので、下は**たたき台**。自分のプロジェクトのコマンドに置き換えてください。

## 設定例（プロジェクトの `.claude/settings.json`）

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "npm run lint --silent && npm test --silent"
          }
        ]
      }
    ]
  }
}
```

- `PostToolUse`：ファイルを編集・作成した**あと**に走る。
- `matcher`：`Edit|Write` のとき＝ファイルを直したとき。
- `command`：実際に走らせるチェック。上は例（`npm run lint` と `npm test`）。
  - Python なら `ruff check . && pytest -q`、Go なら `go vet ./... && go test ./...` のように置き換える。

## 注意（安全に使う）
- **設定の追加・変更は内容を確認してから**。重いコマンドを毎回走らせると遅くなるので、軽いチェックにする。
- 設定づくりに迷ったら、Claude Code の設定支援スキル（`update-config`）に相談すると確実です。
- これは「自動チェック」であって、**人のレビュー（⑥）の代わりにはなりません**。両方使います。
