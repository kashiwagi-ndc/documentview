# 仕様メモ（工程③ 反復の計画づくり）— モック文書データ

## 今回やること
- **機能名**：モック文書データの作成
- **今回の目標（スプリントゴール）への寄与**：実システム連携なしに、ツリー・ビューア・比較・切替の画面イメージと動作イメージを固められるようにする土台データ

## 仕様（AIが迷わないように具体的に）
| 項目 | 内容 |
|---|---|
| 対象ファイル | `frontend/src/mocks/documentTree.ts`、`frontend/public/mock-files/`（サンプルPDF・画像ファイル一式） |
| 対象の関数・IF | `documentTree: DocumentTreeNode[]` をエクスポート。`DocumentTreeNode { id: string; name: string; type: "document" \| "attachment"; fileType: "pdf" \| "image"; fileUrl: string; children: DocumentTreeNode[] }`。将来バックエンドAPIのレスポンス形と一致させ、差し替えを容易にする |
| 対象外（やらないこと） | 実データに近い機微情報を含めない（ダミーの社内文書名・氏名等はすべて架空のものにする）、実バックエンドとの接続 |
| 動作確認手順（できたの基準） | ①案件（親文書）が複数件、添付文書を含めてツリーで用意されている／②PDF・画像の両方のサンプルが含まれる／③添付が2段階以上ネストしたケースが最低1件ある／④添付がゼロ件の文書ケースが最低1件ある／⑤複数ページのPDFサンプルが最低1件ある |

## 不確実性（まだ確定していないこと）
