# 仕様メモ（工程③ 反復の計画づくり）— ファイルダウンロード機能

## 今回やること
- **機能名**：ファイルダウンロード機能
- **今回の目標（スプリントゴール）への寄与**：ブラウザ内でプレビューできない添付ファイル（Excel等）を、ダウンロードして手元のアプリで確認できるようにする。あわせて、PDF/画像でも必要に応じてダウンロードできるようにする

## 仕様（AIが迷わないように具体的に）
| 項目 | 内容 |
|---|---|
| 対象ファイル | `frontend/src/features/viewer/DocumentViewer.tsx`（共通ヘッダーのダウンロードボタン）、`frontend/src/features/viewer/UnsupportedFileViewer.tsx`（プレビュー非対応時の代替表示）、`frontend/src/types/document.ts`（`DocumentFileType` に `"other"` を追加）、`frontend/src/utils/file.ts`（拡張子・ファイル名抽出） |
| 対象の関数・IF | `node.fileType` が `"pdf"` `"image"` `"other"` のいずれでも、`DocumentViewer` 上部の共通ヘッダーに `<a download>` のダウンロードボタンを常設する。`fileType === "other"` の場合はビューア本体を `UnsupportedFileViewer` に差し替え、「この形式はプレビューできません。ダウンロードしてご確認ください」という案内と大きめのダウンロードボタンを表示する。今回はモックの静的ファイル（`frontend/public/mock-files/`）をそのままダウンロードさせる |
| 対象外（やらないこと） | 複数ファイルの一括ダウンロード（ZIP化等）、ダウンロード履歴・監査ログの記録（次フェーズで実バックエンド連携時に検討）、Office文書のブラウザ内プレビュー変換 |
| 動作確認手順（できたの基準） | ①PDF/画像を表示中、ヘッダーの「ダウンロード」ボタンでそのファイルがダウンロードされる／②ツリーでExcel等の非対応添付（今回のモックでは`経費内訳（Excel）`）を選ぶと、プレビューの代わりに形式名（拡張子）とダウンロード案内が表示される／③そこから「ダウンロードして確認する」ボタンでファイルがダウンロードされる／④比較モードでも左右それぞれのペインで独立してダウンロードできる |

## 不確実性（まだ確定していないこと）
| 種類 | 内容 | いつ・どう確かめる |
|---|---|---|
| 曖昧性 | プレビュー非対応と判定する形式の範囲（Excel/Wordのみか、CAD図面等も含むか）が未確認 | 次フェーズで基盤システム担当に実際の添付ファイル形式一覧をヒアリング |
| 複雑性 | 実データ連携時、ダウンロードもファイル配信API（[ファイル配信API（共有フォルダ連携）.md](ファイル配信API（共有フォルダ連携）.md)）経由になる。機微文書のダウンロードを許可してよいかは既存の業務ルール次第 | 次フェーズで情シス・基盤システム担当に確認 |
