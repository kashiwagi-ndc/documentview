# 仕様メモ（工程③ 反復の計画づくり）— 文書メタ情報表示

> **表記について**：画面上の表示名は「**伝票情報**」（社内の呼び方に合わせて2026-08-29に変更）。本ファイル・コード上の内部名称（`MetaField`／`metadata`／ファイル名等）は変更していない。

## 今回やること
- **機能名**：文書メタ情報表示
- **今回の目標（スプリントゴール）への寄与**：ツリー最上位の文書が持つテキスト形式のメタ情報（ラベル＋内容、入れ子・明細対応）を、文書本体（PDF/画像）と一緒にブラウザ上で確認できるようにし、承認者が項目をひとつずつレビューできるようにする

## 前提（ヒアリングで確定した事項）
| 項目 | 内容 |
|---|---|
| メタ情報を持つ対象 | ツリーの**最上位の文書**（`type: "document"`）のみ。添付文書（`type: "attachment"`）は対象外 |
| データ形式 | テキストデータ。JSON同様、ラベル（項目名）＋内容の並び。入れ子構造もあり得る |
| 入れ子の種類 | ①1件だけのグループ（例：申請者情報）②繰り返し行＝明細（例：経費明細、支払スケジュール） |
| 想定項目数 | 10〜100項目程度。明細があればさらに増える |
| 表示方針 | 文書ビューア（PDF/画像）に加えて表示。承認者が項目をひとつずつ確認しやすいレイアウトにする |

## レイアウト設計（検討したポイント）
- **配置**：ビューアの**下**に「伝票情報パネル」として配置。タブ切替（文書／伝票情報を行き来する）にはしなかった——承認者は文書の内容と伝票情報を**見比べながら**確認する使い方が主だと考え、両方を同時に見られることを優先した。
- **高さ**：既定で240px程度の高さを確保しつつ、パネル上端の**ドラッグで高さを調整**できるようにした（120〜560pxの範囲）。100項目規模でも、必要なときだけ大きく広げられる。
- **折りたたみ**：パネル見出し（「▸ 伝票情報（n項目）」）をクリックすると全体を閉じられる。文書内容だけに集中したいときに畳める。
- **絞り込み**：項目数が多い（最大100+）ケースを想定し、ラベル・値のテキストで絞り込む検索欄を用意した。
- **入れ子の表現**：
  - 単純な項目：ラベルを左、内容を右に並べる2カラムの行（一覧性重視、1行あたりの高さを抑えて多項目でもスキャンしやすくした）。
  - 1件だけのグループ（`children`）：グループ名をクリックで開閉できる小見出し＋インデントした子項目リスト。
  - 明細（`items`、繰り返し行）：ラベル×値の縦積みではなく**表形式**にした。同じ列が並ぶ行データは、繰り返しブロックより表の方が圧倒的に読み取りやすいため。
- **対応外の入れ子**：明細の行の中にさらに入れ子グループ／明細を持つケース（3階層目の繰り返し）は今回未対応。実データでそのようなケースがあれば次回検討する。

|---|---|
| 対象ファイル | `frontend/src/types/document.ts`（`MetaField` 型・`DocumentTreeNode.metadata` 追加）、`frontend/src/utils/metaField.ts`（値の整形・項目数カウント・絞り込み）、`frontend/src/features/meta/MetadataPanel.tsx`（開閉・高さ調整・検索を持つパネル本体）、`frontend/src/features/meta/MetaFieldGroup.tsx`（再帰的な項目描画、入れ子グループの開閉）、`frontend/src/features/meta/MetaFieldTable.tsx`（明細の表描画）、`frontend/src/features/viewer/DocumentViewer.tsx`（`node.type === "document"` かつ `metadata` がある場合にパネルを追加表示） |
| 対象の関数・IF | `MetaField { label; value?; children?: MetaField[]; items?: MetaField[][] }` を基本形とする。`<MetadataPanel fields={node.metadata} />` は文書切替のたびに `key={node.id}` で状態（開閉・高さ・検索語）をリセットする |
| 対象外（やらないこと） | メタ情報の編集・入力（表示専用）、メタ情報と文書本文の項目同士の自動突合（別機能として将来検討）、明細内のさらなる入れ子（3階層目の繰り返し）、実データ連携（基盤システムからのメタ情報取得は次フェーズ） |
| 動作確認手順（できたの基準） | ①最上位の文書を選ぶとビューア下に「伝票情報」パネルが表示される／②添付文書を選ぶとパネルは表示されない／③単純項目・1件だけのグループ（開閉可）・明細（表形式）のいずれも正しく表示される／④検索語を入れると一致する項目（グループ・明細行を含む）だけに絞り込まれる／⑤パネル見出しクリックで全体を折りたためる／⑥パネル上端をドラッグして高さを調整できる／⑦比較モードでは各ペインが独立して自分の文書の伝票情報を表示する |

## 不確実性（まだ確定していないこと）
| 種類 | 内容 | いつ・どう確かめる |
|---|---|---|
| 曖昧性 | 実際のメタ情報の項目名・階層構造（本当にJSON同等の任意の入れ子があり得るか、明細は本当に「行×列」の単純な表で表現しきれるか）が未確認 | 次フェーズで基盤システム担当にメタ情報のスキーマ・サンプルデータをヒアリング |

| 変動性 | 100項目を大きく超えるケース（例：数百行の明細）があった場合、現在の単純な表描画で十分かは未検証 | 実データの規模感が分かった時点で、必要なら仮想スクロール等を検討 |
