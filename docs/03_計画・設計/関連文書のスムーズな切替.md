# 仕様メモ（工程③ 反復の計画づくり）— 関連文書のスムーズな切替

> **経緯**：プロトタイプ確認1回目で「前へ／次へボタンは不要、その分ビューアを大きく」というフィードバックを受けていったん削除したが、確認2回目で「ツリーを隠した状態では文書を切り替える手段がなくなってしまう」という理由で復活を依頼された。**表示領域を圧迫しない**という当初の要望を満たすため、独立した操作行を追加するのではなく、既存のヘッダー行（文書名＋ダウンロードボタンの行）に前後移動ボタンを組み込む形で再実装した（2026-08-29）。

## 今回やること
- **機能名**：関連文書のスムーズな切替
- **今回の目標（スプリントゴール）への寄与**：ツリーを都度開き直さなくても、また文書ツリーを隠していても、表示中の文書から前後の関連文書へすばやく移動できるようにする

## 仕様（AIが迷わないように具体的に）
| 項目 | 内容 |
|---|---|
| 対象ファイル | `frontend/src/features/viewer/DocumentViewer.tsx`（前後移動ボタンの実装本体）、`frontend/src/features/compare/CompareViewer.tsx`（各ペインへの伝播）、`frontend/src/pages/DocumentReviewPage.tsx`（ツリーのフラット化リストと移動先反映） |
| 対象の関数・IF | `<DocumentViewer node flatList onNavigate />` のヘッダー行内、文書名の左右に `◀`/`▶` の小さな矢印ボタンを配置（新しい行は追加しない＝ビューア本体の表示領域は変わらない）。`flatList`（ツリーをフラット化した表示順の配列）内で現在の文書の前後を求め、先頭・末尾では該当ボタンが無効化される。単票表示では選択文書を、比較表示では各ペインごとに独立してそのペインの文書だけを切り替える（比較表示のペイン割り当てには影響しない） |
| 対象外（やらないこと） | キーボードの `←`/`→` によるショートカット操作（今回は見送り。必要になれば追加検討）、ツリー全体を横断した任意順の並べ替え、お気に入り／最近見た文書の履歴機能 |
| 動作確認手順（できたの基準） | ①単票表示中に▶を押すと、ツリー表示順で1つ次の文書に切り替わり、ツリー側の選択状態も連動する／②先頭・末尾では該当ボタンが無効化される／③文書ツリーを「隠す」で非表示にした状態でも、◀▶ボタンで文書を切り替えられる／④比較表示では各ペインが独立して前後移動でき、他のペインに影響しない／⑤ボタンを追加してもビューアの表示領域（縦横のサイズ）が前後移動ボタン追加前と変わらない |
