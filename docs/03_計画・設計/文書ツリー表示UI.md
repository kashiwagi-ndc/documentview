# 仕様メモ（工程③ 反復の計画づくり）— 文書ツリー表示UI

## 今回やること
- **機能名**：文書ツリー表示UI
- **今回の目標（スプリントゴール）への寄与**：承認者が文書と添付文書の構成をひと目で把握し、確認したい文書を選べるようにする

## 仕様（AIが迷わないように具体的に）
| 項目 | 内容 |
|---|---|
| 対象ファイル | `frontend/src/features/tree/DocumentTree.tsx`、`DocumentTreeNode.tsx`、`useDocumentTree.ts`、`frontend/src/mocks/documentTree.ts` |
| 対象の関数・IF | `useDocumentTree()` フックが `frontend/src/mocks/documentTree.ts` のモックツリーデータを返す（今回はAPI呼び出しなし。後で実APIに差し替えられるよう戻り値の形は将来のAPIレスポンスと同じにする）。`<DocumentTree nodes={...} onSelectDocument={(node) => void} />`。文書種別（`type`/`fileType`）に応じたアイコン表示 |
| 対象外（やらないこと） | ドラッグ&ドロップでの並べ替え、右クリックメニュー、ツリー項目の編集・削除、複数選択（今回は単一選択のみ）、実バックエンドとの通信 |
| 動作確認手順（できたの基準） | ①ツリーが階層構造（親文書の下に添付文書がインデントされた状態）で表示される／②PDFと画像でアイコンが区別される／③ノードをクリックすると `onSelectDocument` が呼ばれ、選択状態が視覚的にわかる／④階層が深い・添付が多いケースでも折りたたみ／展開ができる |

## 不確実性（まだ確定していないこと）
| 種類 | 内容 | いつ・どう確かめる |
|---|---|---|
| 変動性 | 添付文書の階層が何段まであり得るか（1段のみ／多段）が実データ未確認 | モックデータでは多段ケースも用意して見た目を確認しておき、実データ確認は次フェーズで |
| 曖昧性 | 文書の「承認状態」等をツリー上にバッジ表示すべきか未定（今回は表示しない前提） | プロトタイプを見ながらユーザーと確認 |
