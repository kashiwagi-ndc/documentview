# 仕様メモ（工程③ 反復の計画づくり）— タブレット表示対応・ツリー幅調整

## 今回やること
- **機能名**：タブレット表示対応・文書ツリー幅の調整
- **今回の目標（スプリントゴール）への寄与**：タブレットでもビューア（PDF等）の表示幅を十分に確保できるようにし、最低限のタブレット表示に対応する

## 前提（ヒアリングで確定した事項）
| 項目 | 内容 |
|---|---|
| 対応範囲 | **タブレットまで**対応する（スマートフォン、特に縦持ちは前回のヒアリングで対応不要と確認済み）。フル書きレスポンシブではなく、タブレット幅で崩れず・PDF幅が狭くなりすぎないことが最低限のゴール |
| きっかけ | 「今の表示ではPDFの表示幅が狭すぎる」というフィードバック。原因はツリーサイドバーが常に固定300pxだったこと |

## 仕様（AIが迷わないように具体的に）
| 項目 | 内容 |
|---|---|
| 対象ファイル | `frontend/src/pages/DocumentReviewPage.tsx`（サイドバー幅の状態管理・ドラッグ処理）、`frontend/src/App.css`（`.sidebar-resizer` 等） |
| 対象の関数・IF | ①**既定幅の自動調整**：初回表示時に `window.innerWidth` を見て、900px未満（タブレット相当）なら既定のツリー幅を220px、それ以上なら300pxにする（`getDefaultSidebarWidth()`）。②**ドラッグでの幅調整**：ツリーとビューアの境界に `.sidebar-resizer`（幅6px、`cursor: ew-resize`）を配置し、ポインタードラッグで180〜480pxの範囲でツリー幅を動的に変更できる。③既存の「◀ ツリーを隠す」による完全な非表示（幅0）はそのまま維持し、"狭める"（ドラッグ）と"隠す"（ボタン）の両方を用意した |
| 対象外（やらないこと） | スマートフォン（特に縦持ち）向けのレイアウト崩れ対応、画面回転時の自動追従（初回表示時の幅のみ画面幅を見て決定。以降はユーザー操作のみで変わる）、比較モードのペイン数（2/3枚）を画面幅に応じて自動制限する機能 |
| 動作確認手順（できたの基準） | ①タブレット幅（768〜1180px相当）で、初期表示時にツリー幅が狭め（220px）になり、PDFがデスクトップよりゆったり表示される／②ツリーとビューアの境界をドラッグすると、リアルタイムでツリー幅が変わりPDF幅も追従する／③タブレット幅で3枚比較モードにしても、崩れずに3ペイン＋伝票情報パネルが表示される／④「ツリーを隠す」で完全非表示にできることは従来通り |
