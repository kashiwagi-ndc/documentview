# 仕様メモ（工程③ 反復の計画づくり）— 文書ビューア（PDF・画像 単票表示）

## 今回やること
- **機能名**：文書ビューア（PDF・画像 単票表示）
- **今回の目標（スプリントゴール）への寄与**：ツリーでクリックした文書をブラウザ上でそのまま閲覧できるようにする（承認判断に必要な内容確認）

## 仕様（AIが迷わないように具体的に）
| 項目 | 内容 |
|---|---|
| 対象ファイル | `frontend/src/features/viewer/DocumentViewer.tsx`、`PdfViewer.tsx`（`pdfjs-dist`/`react-pdf` 利用）、`ImageViewer.tsx`、`frontend/public/mock-files/`（サンプルPDF・画像を配置） |
| 対象の関数・IF | `<DocumentViewer node={selectedNode} flatList onNavigate />` が文書名＋前後移動ボタン（◀▶）＋ダウンロードボタンの共通ヘッダーを表示した上で、`node.fileType` に応じて `PdfViewer` / `ImageViewer` / `UnsupportedFileViewer`（[ファイルダウンロード機能.md](ファイルダウンロード機能.md)参照）を出し分ける。前後移動は既存のヘッダー行に組み込む形で実装し、新しい行は追加しない＝ビューア表示領域は変わらない（詳細は[関連文書のスムーズな切替.md](関連文書のスムーズな切替.md)）。ファイルURLはモックツリーデータ内の `fileUrl`（`/mock-files/xxx.pdf` 等の静的パス）をそのまま使う（今回はAPI呼び出しなし）。PDFはページ送り・拡大縮小に加え「幅に合わせる」ボタンでペイン幅に合わせた拡大率を計算して適用する（文書を開いた直後は自動で1回フィットし、以降のページ送りではユーザーが選んだ拡大率を維持）。画像は拡大縮小・フィット表示に対応 |
| 対象外（やらないこと） | PDFへの注記・マーカー・ハイライト機能、印刷機能、実バックエンドとの通信、左右比較時のページ送り同期（対象外と確認済み） |
| 動作確認手順（できたの基準） | ①ツリーでPDFを選択→ブラウザ内にページが表示され、ページ送り・拡大縮小ができる／②ツリーで画像を選択→画像が表示され拡大縮小ができる／③複数ページのPDFで現在ページ番号が表示される／④存在しないファイルパスの場合にエラー表示になり画面が壊れない／⑤PDFを開いた直後、ペイン幅に合わせた拡大率で自動表示される／⑥「幅に合わせる」ボタンで、拡大・縮小した後でも元のフィット表示に戻せる／⑦ヘッダーの◀▶で前後の関連文書へ移動でき、ビューアの表示領域サイズは変わらない |

## 不確実性（まだ確定していないこと）
| 種類 | 内容 | いつ・どう確かめる |
|---|---|---|
| リスク（機会） | 大容量PDF（数十MB・数百ページ）でのブラウザ表示パフォーマンス劣化 | `pdfjs-dist` の遅延読み込み・仮想スクロールで対応。実データの規模感は次フェーズで基盤システム担当に確認 |

**解消済み**：「幅に合わせる」ボタンがPDFに存在しなかったのは実装漏れ（画像ビューアにのみ実装していた）で、ページ数とは無関係だった。PDFにも実装し、初回表示時は自動フィットするようにした。
